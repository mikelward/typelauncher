- Persist `InstalledApp.disambiguator` in `AppMetadataStore` so cached metadata renders the regional badge ("US" / "UK" / "INTL") on the very first frame of a warm start. Today `LauncherViewModel.applyDisambiguators()` recomputes the map on every `loadInstalledApps` (cold start, package-event reload, etc.), and the cached `InstalledApp` round-tripped through `AppMetadataStore` always comes back with `disambiguator = null` — so for the brief window between cached-metadata prefill and the fresh `LauncherApps` load, regional siblings (Chase US / Chase UK, Amex US / Amex UK / Amex AU) all render unbadged.

  **Options considered:**
  1. **Persist `disambiguator` in `AppMetadataStore` (recommended).** Add a `disambiguator` JSON field to `AppMetadataStore.save` / `.load`. The recompute on the next reload remains the ground truth, so a stale persisted badge self-heals as soon as the package set churns; old snapshots without the field gracefully load with `disambiguator = null` (current behaviour). Wins first-frame correctness for warm starts at the cost of a single extra string per app in the snapshot.
  2. **Recompute disambiguators on the cached metadata at construction time.** Run `applyDisambiguators()` against the cached `InstalledApp` list before publishing the prefill state. Avoids the new persisted field but pays the recompute cost twice (once now, once after the fresh load). Recompute is cheap (O(n), sub-millisecond), so this is the lower-risk option if the JSON field feels like overreach.
  3. **Do nothing.** The unbadged window is short (one or two frames on a typical warm start). Acceptable if no one reports it; revisit if regional siblings become visually confusable for users in practice.

  **Do *not* also persist `customName` in `AppMetadataStore`.** It would be redundant with `RenamedAppStore`, and the first-frame argument that drives the disambiguator change does not apply: `RenamedAppStore` is read synchronously at `LauncherViewModel` construction, and `markVisibility()` already applies the override during the cached-metadata prefill, so the rename shows up on frame zero. Persisting `customName` in two places would create a second source of truth (and a sync hazard: every `renameApp` write would have to re-save the metadata snapshot to keep them aligned, or accept that the cached label can briefly disagree with the override store after a rename). The current "RenamedAppStore is the source, AppMetadataStore is purely the system snapshot" split keeps each store responsible for one thing.
