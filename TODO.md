- Reconsider `android:windowSoftInputMode="stateAlwaysVisible|adjustResize"` on `MainActivity` (`AndroidManifest.xml:31`). The attribute predates the View→Compose migration (`908ebe0`); IME insets are now handled inside Compose via `Scaffold(contentWindowInsets = … .union(WindowInsets.ime))` (`TypeLauncherApp.kt:130`), so the manifest mode is double-handling. Likely target: `adjustNothing` (or omit), and replace `stateAlwaysVisible` with an explicit `SoftwareKeyboardController.show()` keyed on the home search field's focus.
    - Pros: removes the window-level resize on resume/IME show, so Compose lays out once instead of after a system-driven resize; lets non-Home pages (Settings, Widgets, Agenda) keep the IME hidden by default; aligns with how AOSP Launcher3 / Pixel Launcher handle the home activity.
    - Cons: requires wiring an explicit IME-show in Compose so the home search keeps its current always-on-keyboard behavior (the property `67179b1 Keep home search keyboard visible` was added for); risk of regressing that behavior if the focus/show effect isn't keyed correctly; a brief frame where the IME is not yet visible after cold start.
    - Possible symptoms of the current setting: momentary dark/blank band at the bottom of the screen on resume from another app while the window resizes before Compose re-lays out; IME appearing on Settings / Widgets / Agenda screens where it shouldn't; jank on first frame after `onResume` because the window content area changes size after `setContent` has already measured.
