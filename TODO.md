# TODO

- Extend the widget picker filter to also match individual widget labels (and possibly description) within an app group, not just the app group names. Today (`WidgetsScreen.kt`'s `WidgetPickerCard`) only filters by `WidgetProvider.appName`.
- Consider extracting a shared filter input composable so the widget picker filter and the home `SearchCard` share styling and clear-button behavior instead of duplicating the `OutlinedTextField` setup.
- Default the launcher palette to the Material 3 system theme colors (selection highlight, foreground/text, primary, background) instead of hard-coding values. The active-app highlight in `AppRow` and `IconOnlyAppButton` (`HomeScreen.kt`) is currently a fixed pale blue, and `TypeLauncherTheme.kt` carries hard-coded `lightScheme`/`darkScheme` fallbacks for primary/secondary/background/etc. They were picked because dynamic color was making the M3 tokens blend into the card surface; revisit once we decide how the launcher should track wallpaper-derived dynamic colors so the highlight and other accents stay visible without overriding the theme.
- Decide whether empty-query Enter/Search should continue opening Type Launcher settings or do something else.
- Generalise the per-surface dedup setting into a single `Merge sections` option that, when on, treats the notification bar, recents row, dock, and main app list as one merged surface — every app appears in exactly one section (the highest-priority one it qualifies for) and the main list drops anything visible above. Today only `Hide recents from app list` ships, scoped to the visible recents window; the dock-vs-list dedup is hard-coded to always-on, and the notification bar isn't deduplicated at all. The follow-up should: (1) collapse `Hide recents from app list` and any future dock/notification toggles into one switch, (2) decide a section priority order (likely notifications > recents > dock > main), (3) handle the visible-window scoping for recents that the current toggle uses, (4) keep the Enter-fallback consistent so a typed query that only matches a deduped section still launches.
- Design keyboard access for launching docked apps.
- Disambiguate multiple installed apps with the same display name, for example by showing package name, profile, or another stable identifier.
- Decide how the regional disambiguator badge (full-width bottom strip in `AppIcon`, `HomeScreen.kt`) should coexist with the OEM-rendered work-profile briefcase. The briefcase is baked into the icon bitmap at the bottom-right corner, and `computeDisambiguators` (`AppDisambiguation.kt`) only suppresses the badge for *same-package* personal/work clones via the `group.distinctBy { it.packageName }.size < 2` skip. A cross-package, cross-profile ambiguity group (e.g. personal `com.foo.uk` + work `com.foo.us`) still emits a badge on the work entry, and the bottom strip then bisects the briefcase — neither glyph reads cleanly. Considered cheap fixes: (a) skip the badge for `isWorkApp == true` either at compute or render time and rely on the `(US)`/`(UK)` parenthesised label suffix that already ships, or (b) leave the bottom-right ~25 % of the strip clear so the briefcase stays visible. Deferred because the triggering case is rare in practice (Codex flagged it on PR #217); revisit before any change widens the regional-marker set or the work-profile pipeline.
